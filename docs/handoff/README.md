## 1. 12주차 제출물 (수업 안내 기준)

**제출은 최원준이 한 번에 합니다.** 모든 파일은 **일요일 22:00까지** 최원준에게 전달합니다.

## 2. 공통 원칙

- **일정은 각자 상황에 맞게 유동적으로 바꿔도 됩니다.** 문서의 시각은 권장안입니다. 다만 **다른 사람이 기다리는 전달 기한**(아래 5. 선행 작업 표)과 **동결 시각**(6-4)이 바뀌면 미리 단톡방에 알려 주세요.
- **프로그래밍은 최원준·김가연만** 합니다. 박한희·김나연은 코드를 다루지 않고, 결과물은 표·문서·파일로 최원준에게 넘깁니다.
- **디자인은 기능이 다 끝난 뒤(일요일 13시부터) 최원준이 새로 합니다.**
- 코드는 `main`에 직접 올리지 않고 **브랜치 → PR → 최원준 확인 후 merge** 순서로 합니다.
- **인증키(`.env`)는 단톡방·문서·저장소 어디에도 붙여 넣지 않습니다.** 네이버 지도 키는 최원준이 김가연에게 **1:1 개인 메시지로만** 전달하고, 김가연은 로컬 `.env`에만 넣습니다.
- **금요일 저녁~토요일 낮은 최원준과 연락이 어렵다고 보고** 일을 짭니다. 물어볼 게 있으면 오늘과 금요일 낮에 묻고, 그 뒤는 각자 판단해서 진행합니다.
- 전달 기한을 넘기면 그 항목은 **제출 후**에 반영합니다 (아래 "자르는 순서"). 기한을 못 맞출 것 같으면 기한 전에 단톡방에 알립니다.

### 6-2. `i18n/*.json` 규칙 (가장 충돌하기 쉬운 곳)

1. 김가연은 `origin_note`와 **새로 만드는 키**만 4개 언어 파일에 추가합니다. 기존 키는 수정하지 않습니다. PR 설명에 새 키 목록을 적습니다.
2. 최원준은 **김가연의 PR이 merge된 뒤에** 번역표를 반영합니다. 반영은 키별로 값만 바꾸고, 파일 전체를 다시 만들지 않습니다.
3. 김나연은 번역 검수에서 **`origin_note`는 건드리지 않습니다** (김가연이 문구를 새로 쓰기 때문). 번역표에 없는 새 키는 일요일에 영·중·일 화면에서 확인만 합니다.

### 6-3. PR 순서와 merge 순서

**김가연의 PR은 한 줄로 이어서 쌓습니다** (같은 사람이 앞 브랜치에서 다음 브랜치를 따므로 서로 충돌하지 않음). 금·토에는 최원준이 merge할 수 없기 때문입니다.

```
main ← feature/location (PR-1a, 목)
        ← feature/name-en (PR-1b, 목)           ← location에서 분기
            ← feature/naver-map (PR-M, 금)       ← name-en에서 분기
                ← feature/dong-chips (PR-2, 토)   ← naver-map에서 분기
```

- 일부가 안 끝나도 **앞의 PR만 먼저 merge**됩니다. 마지막 PR-2가 토요일 20:00까지 안 끝나면 일요일 11:00까지 새 `main`에서 다시 시작합니다.

**토요일 22:00~00:30 최원준 merge 세션** (중간에 멈춰야 하면 앞 단계까지만 push):

1. 김가연 PR을 위 순서대로 merge (PR-1a → PR-1b → PR-M → PR-2) → `python -m pytest`
2. **Production 배포에서 네이버 지도가 뜨는지 확인**. 키가 없는 로컬 실행에서는 OSM으로 자동 전환되는지도 확인
3. 번역표 반영 (`origin_note` 제외)
4. 브랜드표 → `data/conglomerate_brands.txt`
5. 테스트에서 나온 이상한 장소 → 제외 규칙
6. **`collect_google.py` 실행** (하루 한도 안에서, 약 15분) → `build_places.py` 재실행 (`descriptions.json`과 구글 데이터가 합쳐지는지 확인) → `python -m pytest` → push
7. 김가연에게 "`places.json` 바뀜, 일요일 아침에 pull"이라고 알림

일요일: **12:00 동결** → 최원준이 `design/final` 브랜치를 새로 따서 디자인 시작.

### 6-4. 동결 시각

|---|---|---|
| 일 12:00 | 기능, 데이터(`places.json`), 번역 | 치명적 버그 수정만 (김가연: `core/`, `app.py`, `map.js`, **16:00까지**) |
| 일 16:00 | 디자인 | 오타·깨짐 수정만 |
| 일 21:00 | 제출용 압축 | 파일 교체 금지 (새로 압축할 땐 클린 실행 재확인) |

### 6-5. Git 사용 규칙

- 브랜치 이름: `feature/location`, `feature/name-en`, `feature/naver-map`, `feature/dong-chips`, `design/final`
- 작업 시작 전 항상 `git switch main && git pull` (이어 쌓는 브랜치는 앞 브랜치에서 분기)
- `git add -A` 금지. **바꾼 파일 이름을 지정해서** `git add` (특히 `data/places.json`, `trippin.db`, `.env`가 실수로 올라가지 않게)
- 충돌이 나면 PR을 올린 사람이 아니라 **merge하는 최원준이 풉니다**

## 7. 시간이 모자랄 때 자르는 순서

앞에서부터 먼저 버립니다. 보고서와 실행 파일, 영상이 우선입니다.

1. 카테고리 칩 (김가연 PR-2의 일부)
2. 구글 수집 범위 축소 (상위 후보를 줄이고 관광공사 107곳만. 수집 못 한 장소는 중립값 0.5)
3. 동네 필터 (동네 요약만 남김)
4. 영문 장소 이름 (PR-1b)
5. 디자인 범위 축소 (보고서 핵심 화면 3장만: 검색 결과, 점수 상세, 대시보드)
6. 사용자 테스트 추가 반영
7. 번역 반영 (제출 후)

**절대 자르지 않는 것:** 현재 위치(서울 시연 필수), 네이버 지도(막히면 OSM 폴백으로 제출), 구글 점수 반영(범위 축소까지만), 보고서, 실행 확인, 영상(백업본 포함).
