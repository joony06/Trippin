# 박한희 — 최종보고서, 브랜드 검증, 사용자 테스트

코드는 다루지 않습니다. 결과물은 문서·표로 최원준에게 전달합니다.

## 1. 최종보고서 작성 총괄 (13쪽 초과 시 감점)

양식은 중간보고서와 같고, **중간 대비 달라진 점과 그 이유**가 핵심입니다. 첫 페이지에 프로젝트명·팀원·팀번호(13팀).

| 섹션 | 권장 분량 | 자료 받을 곳 |
|---|---|---|
| 1. 개요 및 목표 | 1쪽 | 중간보고서 그대로 + 변경 없음 명시 |
| 2. 기능 소개 (추가·변경·삭제) | 3쪽 | 아래 "변경 사항 표" |
| 3. 개발된 프로그램 구조 (순서도) | 3쪽 | 최원준이 파일 구조·알고리즘 설명 전달 |
| 4. 개발 결과 화면 | 3쪽 | 최원준이 최종 디자인 후 캡처 전달 |
| 5. 업무 분장 (변경 전/후, 이유) | 1쪽 | 아래 "업무 분장 변경" |
| 6. 스케줄 (간트차트, 변경 전/후) | 1쪽 | 팀 단톡방 기록 |
| 7. 기대 효과 | 1쪽 | 중간보고서 + 실제 데이터 규모 반영 |

### 변경 사항 표 (초안 — 확인 후 보고서에 반영)

| 구분 | 중간보고서 | 최종 | 이유 |
|---|---|---|---|
| 장소 데이터 | 샘플 13곳 | 공공데이터 약 3,500곳 (한국관광공사 TourAPI + 소상공인시장진흥공단 상가정보) | 실제 데이터로 검증 |
| 영업시간 | 네이버 지도에서 수집 | 수집 안 함 (구글 연동 시 구글로 대체) | 네이버는 영업시간 공식 API가 없고 크롤링은 허용 범위 문제 |
| 하드 필터 | 대기업 계열 제외 | 대기업 계열 + **대형 프랜차이즈**(대전 내 지점 10곳 이상) 제외 | 광고비를 쓸 수 있는 대형 체인을 빼야 소상공인 노출 목표에 맞음. 전국 가맹점 수 API는 가명정보 승인 절차가 필요해 대전 상가정보로 대체 |
| 장소 선별 | (없음) | 관광객이 갈 수 없는 곳 제외: 주점, 구내식당, 기관·단체 | 개발 중 직접 테스트에서 '중구청직원상조회' 등 발견 |
| S1 계산 | 고른 카테고리 기준 | 카테고리를 하나도 안 고르면 S1을 빼고 나머지 가중치를 1로 다시 맞춤 | 0으로 나누는 경우 처리 |
| S4·S5 | 구글 평점·리뷰 수 | (카드 등록 여부에 따라) 실제 값 또는 전부 중립값 0.5 | 최원준이 결정 후 알려줌 |
| 지도 | 네이버 지도 | OpenStreetMap (네이버 키 발급 시 교체) | 카드 등록 필요 |
| 다양성 보정 | 0.9^k | 같음 (계산 속도만 개선) | 3,500곳에서도 빠르게 |

### 업무 분장 변경 (초안)

- 프로그래밍: 최원준(데이터·백엔드·통합·디자인), 김가연(검색·지도)
- 박한희·김나연: 개발 제외 → 보고서·검증·영상·발표자료 담당으로 변경
- 이유: 팀원별 역량에 맞춰 개발과 문서 작업을 분리
