## 1. 최종보고서 작성 (13쪽 초과 시 감점)

양식은 중간보고서와 같고, **중간 대비 달라진 점과 그 이유**가 핵심입니다. 첫 페이지에 프로젝트명·팀원·팀번호(13팀). 워드 프로그램으로 작성한 뒤 **PDF**로 제출합니다. **일요일 마무리는 김나연**이 하므로, 내가 쓰는 초안에는 아래 표시를 달아 두세요.

- **[확정 대기]**: 일요일 12:00 최원준이 어디까지 반영됐는지 알려 주면 김나연이 확정할 부분 (2장 기능 목록, 지도·구글 수집 범위)
- **[캡처 대기]**: 일요일 16:30 최종 화면 캡처가 와야 채워지는 부분 (4장)

| 섹션 | 권장 분량 | 자료 받을 곳 | 누가·언제 |
|---|---|---|---|
| 1. 개요 및 목표 | 1쪽 | 중간보고서 그대로 + 변경 없음 명시 | 박한희, 금 |
| 2. 기능 소개 (추가·변경·삭제) | 3쪽 | 아래 "변경 사항 표" | 박한희 초안(금~토, [확정 대기]) → 김나연이 일 12:00 이후 확정 |
| 3. 개발된 프로그램 구조 (순서도) | 3쪽 | 김가연 `알고리즘_구조설명.md`(**토 20:00**), 최원준 `data/` 설명 메모(일 10:30, 김나연에게) | 박한희 토 초안 → 김나연이 일 오후 보강 |
| 4. 개발 결과 화면 | 3쪽 | 최원준이 최종 디자인 후 캡처 전달 (**일 16:30**, 김나연에게) | **김나연** (박한희는 레이아웃 틀만 [캡처 대기]로) |
| 5. 업무 분장 (변경 전/후, 이유) | 1쪽 | 아래 "업무 분장 변경" | 박한희, 금 |
| 6. 스케줄 (간트차트, 변경 전/후) | 1쪽 | 팀 단톡방 기록 + 이번 주 일정표([일정표.png](일정표.png) 참고) | **김나연**이 간트차트 작성 (금), 박한희가 내용 점검 |
| 7. 기대 효과 | 1쪽 | 중간보고서 + 실제 데이터 규모 반영 | 박한희, 금 |

3장 자료가 늦으면 README와 중간보고서의 알고리즘으로 직접 쓰고, 김나연이 일요일에 보강합니다.
