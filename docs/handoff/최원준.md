# 최원준 — 남은 작업

담당(중간보고서): 구글 리뷰 API 연동(S4·S5), 영업 요일·시간 수집, 대시보드 데이터 집계, 장소 데이터 정리·설명문 생성
추가: 전체 통합(PR 확인·merge), 배포, 최종 디자인, 제출용 압축 파일

## 1. 대시보드 시연 데이터 — 바로 가능

- [ ] `data/seed_demo.py`: 가짜 관광객 계정(내·외국인 섞어서)과 최근 7일 조회·찜·리뷰 기록 생성
- [ ] 시연할 가게 1~2곳 정해서 사업자 계정 연결 (`demo_owner` 등)
- [ ] 시연 계정 아이디·비밀번호를 김나연에게 전달 (영상 촬영용)

## 2. 구글 평점·리뷰 수·영업시간 — 팀 결정 필요

- [ ] **카드 등록 여부 결정** (Google Places API는 결제수단 등록 필요, 무료 범위 안에서 사용)
- 등록하는 경우
  - [ ] Google Cloud에서 Places API (New) 키 발급, 하루 사용량 한도 설정
  - [ ] `data/collect_google.py`: 관광공사 장소 + 상위 후보 가게의 `rating`, `userRatingCount`, `regularOpeningHours` 수집
  - [ ] `build_places.py`에 합치기 → S4·S5 실제 값, 영업시간 필터 동작
- 등록하지 않는 경우
  - [ ] 박한희에게 전달: "구글 데이터 없음 → S4·S5 중립값 0.5, 영업시간 필터는 데이터 있는 곳만" (보고서 변경 사항)
- 네이버 영업시간 수집은 **하지 않음** (공식 API 없음, 크롤링 허용 범위 문제) → 보고서 변경 사항으로 이미 전달

## 3. 장소 설명문 AI 생성 — 선택

- [ ] Gemini API 키 발급 (Google AI Studio, 카드 불필요)
- [ ] 관광공사 장소 107곳 한·영 설명문 생성 → `places.json`에 반영
- 안 하면 보고서에서 "미구현 기능"으로 처리

## 4. 다른 팀원 결과물 반영

- [ ] 김가연 PR 확인·merge (기능별로 올라옴)
- [ ] 박한희 브랜드 검증표 → `data/conglomerate_brands.txt` 수정 → `build_places.py` 다시 실행

- [ ] 사용자 테스트에서 나온 이상한 장소 → `build_places.py` 제외 규칙에 추가
