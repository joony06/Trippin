## 1. 검색 전체 흐름

```
[사용자 입력] 검색어·카테고리·최대 거리·예산·방문 요일/시각 + 현재 위치(브라우저)
      │
      ▼
① 출발점 정하기 ── 대전 중구 안이면 브라우저 위치, 밖이거나 위치를 거부하면 대전 중구청 앞
      │
      ▼
② 하드 필터 ── 조건에 안 맞는 곳은 점수 계산 전에 뺌 (카테고리 외에는 제외 이유를 화면에 표시)
      │
      ▼
③ 점수 계산 ── 기준 S1~S6 점수(0~1) × 가중치 → 총점(0~100)
      │
      ▼
④ 정렬·동점 처리 ── 총점 높은 순, 같으면 거리 → 구글 리뷰 수 → 장소 번호
      │
      ▼
⑤ 다양성 보정 ── 같은 대표 카테고리가 위에 k곳 있으면 0.9^k를 곱해 다시 비교 (최대 0.9³)
      │
      ▼
⑥ 화면 표시 ── 상위 30곳 목록·지도, (선택) 동네 필터, 카테고리 칩으로 재검색
```

## 2. 하드 필터 (② 단계)

| 조건 | 빼는 기준 | 정보가 없을 때 |
|---|---|---|
| 카테고리 | 카테고리를 골랐는데 장소 카테고리와 **하나도 맞지 않음** (수천 곳이라 '제외된 곳' 목록에는 넣지 않고, 결과 위에 "고른 카테고리에 맞는 장소만 보여 줘요" 안내) | 카테고리를 안 고르면 이 필터는 없음 |
| 거리 | 출발점과의 거리(하버사인 공식) > 최대 거리(1·2·5·10km) | — |
| 영업시간 | 방문 요일·시각에 영업하지 않음 (자정을 넘기는 영업도 처리) | 영업시간 정보가 없으면 **빼지 않음** |
| 예산 | 입장료 > 예산 | 요금은 수집하지 않아 0원으로 봄 (화면에는 '정보 없음') |
| 대기업 계열 | 공시대상기업집단 브랜드(`conglomerate_brands.txt`) 또는 검수표 판정 | — |
| 대형 체인 | 대전에서 지점명이 붙은 같은 상호가 10곳 이상, 체인 브랜드 목록(`chain_brands.txt`), 또는 검수표 판정 | — |

## 3. 점수 계산 (③ 단계)

**총점 = 100 × Σ (가중치 × 기준 점수)**, 기준 점수는 모두 0~1.

| 기준 | 가중치 | 계산식 | 데이터가 없을 때 |
|---|---|---|---|
| S1 카테고리 일치도 | 0.35 | k ÷ K (K: 고른 카테고리 수, k: 그중 장소와 맞는 수). 하드 필터 때문에 k ≥ 1 | 카테고리를 안 고르면 **S1을 뺌** |
| S2 검색어 관련도 | 0.20 | 이름 또는 **영문 이름**에 포함 1.0 / 카테고리 0.7 / 설명문 또는 **영문 설명문**에 포함 0.4 / 없음 0 (가장 높은 값 하나, 영문은 대소문자 무시) | 검색어가 없으면 **S2를 뺌** |
| S3 거리 | 0.20 | max(0, 1 − d ÷ 10km) | — |
| S4 외부 평점(구글) | 0.10 | (R′ − 1) ÷ 4, R′ = (v·R + m·C) ÷ (v + m), m = 50, C = 4.0 | **중립값 0.5** |
| S5 인기도(리뷰 수) | 0.08 | log(1 + v) ÷ log(1 + v_max) (v_max: 후보 중 최대 리뷰 수) | **중립값 0.5** |
| S6 자체 평점·찜 | 0.07 | 0.7 × (R′자체 − 1) ÷ 4 + 0.3 × log(1 + L) ÷ log(1 + L_max), R′자체는 m = 5, C = 사이트 평균 | **리뷰가 0개면 평점 부분은 0** (찜 부분만 반영), 둘 다 없으면 0 |

- **빠지는 기준이 있으면 남은 가중치의 합이 1이 되도록 다시 나눕니다.** 예: 검색어가 없으면 나머지를 0.8로 나눔.
- R′(베이지안 보정 평점)은 리뷰 수가 적을수록 평균(C) 쪽으로 당겨서, 리뷰 1개짜리 5점이 1위가 되는 것을 막습니다.
- 보고서 계산 예시(A 67.6점, B 46.3점)는 테스트로 그대로 재현됩니다(`tests/test_trippin.py`).

## 4. 정렬·동점·다양성 보정 (④·⑤ 단계)

- **동점 처리:** 총점이 같으면 거리가 가까운 순 → 구글 리뷰 수가 많은 순 → 장소 번호 순.
- **다양성 보정:** 위에서부터 한 곳씩 고르고, 고를 때마다 남은 후보 점수에 **0.9^min(k, 3)**을 곱해 다시 비교합니다(k = 그 후보의 대표 카테고리가 이미 뽑힌 수). 같은 종류(예: 음식점)가 목록 위쪽을 독차지하지 않게 하려는 거예요.
  - **한도 0.9³(약 0.73):** 한도가 없으면 같은 카테고리가 10곳쯤 나온 뒤에는 점수가 원래의 1/3로 떨어져, 조건과 상관없는 곳이 앞으로 올라왔어요. 그래서 팀에서 곱하는 횟수를 3번까지로 정했습니다(사용자 테스트 수정사항 7번).
  - 구현에서는 카테고리별 **대기열(큐, 11주차)**을 점수순으로 만들어 두고, 매번 각 대기열의 맨 앞 후보끼리만 비교해 하나를 꺼냅니다. 같은 카테고리 안에서는 곱하는 값이 같아 순서가 바뀌지 않으므로 결과는 하나씩 다시 비교하는 방식과 같습니다(테스트로 확인).
  - **성능(12주차 빅오):** 남은 후보 전체를 매번 다시 비교하면 O(n²)이지만, 대기열 맨 앞만 비교하면 정렬 O(n log n) + 꺼내기 O(n·c)입니다(n: 후보 수 약 3,000, c: 카테고리 수 최대 10). 하드 필터와 점수 계산은 각각 O(n)입니다.
- 화면에는 보정 전과 보정 후 점수가 함께 나옵니다. 예: `46.7점 (64.0 × 0.9³)`. 상세 화면에는 "같은 대표 카테고리가 위에 n곳 있어 0.9^k를 곱했어요 (최대 0.9³)"라고 안내합니다.

## 5. 파일별 역할

| 파일 | 하는 일 |
|---|---|
| `app.py` | 실행 파일(`python app.py`). 화면 주소(검색·결과·상세·로그인·대시보드)를 처리하고, 주소창 값에서 검색 조건을 읽어(`parse_conditions`) 검색을 실행한 뒤 템플릿에 넘김. 리뷰·찜·조회수 규칙도 여기서 처리 |
| `search.py` | 필터링 검색의 핵심: 하드 필터 → S1~S6 점수 → 정렬·동점·다양성 보정. 거리 계산(하버사인), 기본 출발점, 베이지안 보정 평점 R′도 여기에 있음. 검색 조건은 `Conditions` 클래스 |
| `database.py` | SQLite 데이터베이스. 장소·회원·리뷰·찜·조회 기록 저장과 조회, 사업자 대시보드 통계, 시연용 계정·데이터 |
| `texts.py` + `i18n/*.json` | 화면 문구를 한·영·중·일 4개 언어로 보여 줌. 외국어 화면용 한글 → 로마자 변환 |
| `templates/` | 화면 틀(HTML). 검색 폼, 결과 목록, 장소 상세(점수표), 리뷰, 로그인·가입, 대시보드 |
| `public/map.js` | 지도. 네이버 지도를 불러와 장소 마커·출발점·선택한 장소 강조를 표시 |
| `public/map_leaflet.js` | 네이버 지도를 쓸 수 없을 때(키 없음·로드 실패·인증 실패) 대신 쓰는 OpenStreetMap 지도 |
| `tests/test_trippin.py` | 테스트 22개: 계산식·필터·다양성 보정·현재 위치, 화면 흐름(사업자 자기 가게 리뷰·찜 차단, 조회수 중복 방지, 로그인 전 찜). `python tests/test_trippin.py`로 실행 |
| `data/tools/` | 데이터를 만든 스크립트 (수집·소개문·합치기). 실행에는 필요 없음, 자세한 내용은 「데이터_설명.md」 |

## 6. 추가 기능과 화면 규칙이 흐름에서 들어가는 위치

- **현재 위치** (① 단계): 브라우저가 위치를 검색 폼의 숨은 칸에 넣어 보내면 서버가 대전 중구 안인지 확인해 출발점으로 씁니다. 이 출발점은 거리 필터와 S3에 쓰여요. 서울에서 시연하면 중구 밖이라 대전 중구청 앞을 기준으로 계산하고, 화면에도 그렇게 안내합니다.
- **네이버 지도** (⑥ 단계): 결과 상위 30곳과 출발점을 지도에 표시합니다. 인증키는 환경 변수로만 받고, 키가 없거나 실패하면 OpenStreetMap 지도로 자동으로 바뀌어요(제출용 압축 파일에는 키가 없어서 필요). 외국어 화면에서는 지도 마커 이름도 영문 이름이 있으면 영문으로 보여요.
- **동네별 요약·동네 필터** (⑥ 단계): 순위가 정해진 결과를 동네별로 세어 보여 주고, 동네를 누르면 그 동네만 남깁니다. 검색 계산은 바꾸지 않으므로 순위 번호는 전체 결과 기준이에요.
- **카테고리 칩** (⑥ → 다시 ①): 다른 조건은 그대로 두고 카테고리만 바꿔 검색을 처음부터 다시 합니다.
- **영문 장소 이름** (⑥ 단계): 한국어가 아닌 화면에서는 영문 이름이 있으면 먼저 보여 줍니다(관광공사 장소 39곳, 나머지는 로마자).
- **제외된 곳 목록** (⑥ 단계): 기본으로 접혀 있고, 누르면 펼쳐집니다(휴대폰에서 결과보다 길게 나오지 않게).
- **리뷰·찜·조회수 규칙** (상세 화면, 대시보드 지표에 영향):
  - 사업자는 자기 가게에 리뷰와 찜을 남길 수 없습니다.
  - 조회수는 같은 사람(같은 브라우저)이 같은 날 같은 가게를 여러 번 봐도 1번만 셉니다. 로그인·로그아웃을 해도 마찬가지예요. 사업자가 자기 가게를 본 것은 세지 않습니다.
  - 로그인하지 않은 채 찜을 누르면 로그인 화면으로 갔다가, 로그인한 뒤 보던 가게(검색 조건 포함)로 돌아오면서 찜이 처리됩니다.

## 7. 중간보고서와 달라진 점 (변경 사항 표용)

| 항목 | 중간보고서 | 최종 | 이유 |
|---|---|---|---|
| 카테고리 | 점수(S1)에만 반영 | 하나도 안 맞으면 **하드 필터로 제외** | 사용자 테스트 1번: 고른 카테고리와 상관없는 곳이 결과에 섞여 나옴 |
| S1 | 항상 사용 | 카테고리를 안 고르면 S1을 빼고 가중치를 다시 나눔 | 고른 게 없을 때 모든 곳이 0점이 되는 문제 |
| 하드 필터 | 거리·영업시간·예산·대기업 계열 | + **대형 체인** | 팀 결정: 대기업 계열과 대형 체인 모두 제외 |
| 다양성 보정 | 0.9^k | **0.9^min(k, 3)** | 한도가 없으면 무관한 곳이 위로 올라옴 (수정사항 7번) |
| S2 | 한글 이름·카테고리·설명문 | + **영문 이름·영문 설명문** (대소문자 무시) | 외국인 영어 검색 |
| S6 | 리뷰가 없어도 평점 부분에 사이트 평균 | 리뷰가 0개면 **평점 부분 0** | 찜 1개만으로 점수가 크게 뛰던 문제 |

## 8. 한계·보완점 (알고리즘 쪽)

- 구글 데이터는 지도·검색 대상 3,007곳 중 516곳에만 있어, 나머지는 S4·S5에 중립값 0.5가 들어갑니다. 리뷰가 적은 가게는 데이터가 있으면 오히려 S5가 0.5보다 낮아질 수 있습니다.
- 요금을 수집하지 않아 예산 필터로 빠지는 곳이 실제로는 없습니다.
- 영업시간 정보가 있는 곳이 369곳뿐이라, 나머지는 영업시간 필터에서 빠지지 않습니다.
- S3의 기준 거리는 10km로 고정이라, 최대 거리를 1km로 좁히면 거리 점수 차이가 작습니다.
- 영어 검색은 영문 이름·설명이 있는 관광공사 장소에서만 맞고, 중국어·일본어 검색어는 거의 맞지 않습니다.
- 조회수 중복 방지는 브라우저 쿠키 기준이라, 다른 브라우저나 기기로 보면 다시 셉니다.
